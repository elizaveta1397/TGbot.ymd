## Последний процесс

По порядку за сессию:

1. **`docs/PRIVACY_POLICY.md`** — политика обработки ПДн по структуре
   РКН (6 разделов), реальные данные оператора (Гончарова Елизавета
   Александровна, самозанятая, ИНН 380120953212, г. Железноводск,
   контакт `@goncharova_help`). Доступна командой `/policy` без
   регистрации и согласия.
2. **Экран согласия перед регистрацией** — `handlers/start.py`
   (`start_handler`/`consent_accept`), `keyboards/consent.py`.
   Регистрация (`add_user`) и уведомление админу — только после
   явного нажатия «✅ Согласен(на)». `source` из deep-link держится в
   памяти процесса (`_pending_sources`), не в БД, до согласия.
3. **Правка по ходу (решение Лизы)**: `PRIVACY_POLICY.md` **не должен**
   называть место хранения сервера или конкретных получателей данных
   (Google Sheets/США) — убрано из документа по её прямой просьбе.
   Сама проблема (сервер вне РФ) не решена и остаётся в бэклоге, но
   текст политики её не упоминает. Зафиксировано и в `CLAUDE.md`, и в
   `docs/IDEAS.md` п.1, чтобы не вернуть случайно в будущей сессии.
4. **Удаление данных по запросу** — `/delete_me` с подтверждением
   (`keyboards/delete_me.py`), `database.py::delete_user()` (стирает
   users/user_events/user_parameters), тихое уведомление админу,
   запись в журнал процесса (`print` → `journalctl`, не в БД — та уже
   стёрта). Упомянуто в политике, разд. 6, как мгновенный способ.
   **Не покрывает** выгрузку в Google Sheets — отдельный пункт.
5. **Баг, найденный Лизой при ручной проверке**: без принятого
   согласия всё равно можно было нажимать кнопки главного меню и идти
   по сценариям — экран согласия гейтил только сам `/start`, кнопки
   меню (`F.text == "..."`) ничего не проверяли и срабатывали на любое
   сообщение с нужным текстом (в т.ч. на нажатие кнопки, оставшейся в
   Telegram-клиенте с прошлой сессии). Починено
   `middlewares/consent_gate.py` — глобальный middleware (как
   `ActivityMiddleware`), блокирует любое действие без строки в
   `users`, кроме `/start`, `/policy` и самих кнопок экрана согласия.
6. По ходу сессии удалила себя из БД (`@saeliz`, telegram_id
   250428280) вручную через `delete_user()`, чтобы пройти процесс

7. Нашли смежный, более старый документ — Политика конфиденциальности

## Доступ / как продолжать (не меняется от сессии к сессии)

См. память `server-access-telegram-bot` — ACL, sudoers-путь для
`systemctl` (точное совпадение аргументов, без лишних флагов),
`origin` — HTTPS. Виртуальное окружение `venv/` уже содержит
`gspread`/`google-auth`/`pytest` — `pip install -r requirements-dev.txt`
подтянет то же самое с нуля.

Дашборд-артефакт «Проявка»:
https://claude.ai/code/artifact/8340045d-5ef9-4822-941d-0b33a55bb501

Аккаунтная (не репо-специфичная) память `ru-legal-compliance-risks` —
свод штрафов РФ (152-ФЗ/реклама/касса/налоги/авторские права) + шаблон
аудита сайта на 152-ФЗ. Использовалась и в прошлой, и в этой сессии.
