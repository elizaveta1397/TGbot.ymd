# Правила работы над этим ботом

Свод правил для любой сессии Клода, работающей в этом репозитории.
Читается автоматически при старте.

## Завершение сессии

Чек-лист и порядок действий на конец рабочего дня — в
`docs/SESSION_WRAPUP.md`, триггер по фразам («спокойной ночи»,
«на сегодня всё» и т.п.) — в `SKILL.md`. Текущий статус («на чём
остановились») — в `HANDOFF.md`, перезаписывается каждую сессию.

## Идеи и доработки на будущее

Бэклог идей, которые приходят в голову Лизе по ходу разработки, но не
делаются прямо сейчас — вести в `docs/IDEAS.md` (не путать с
`HANDOFF.md`: там — статус текущей сессии, тут — идеи «когда-нибудь»).
Когда Лиза формулирует идею/доработку на будущее (а не задачу на
сейчас) — записать туда одной строкой, не держать только в памяти
сессии.

## Создание нового процесса

Полный чек-лист (аналитика, уведомления, current_step, работа с
материалами, **обязательные автотесты**) — в
`docs/NEW_PROCESS_CHECKLIST.md`. Читать перед тем, как добавлять
новый хендлер/шаг воронки, а не додумывать по памяти.

## Баги в других процессах, найденные попутно

При создании/изменении любого процесса — по ходу дела проверять код на
баги, не только тот участок, который меняем целенаправленно. Если
что-то найдено:

- сразу предложить Лизе исправить (не чинить молча заодно с другой
  задачей без её решения);
- если чиним сейчас — чинить и сразу же убирать из списка ниже /
  из `HANDOFF.md`;
- если не чиним сейчас — обязательно записать в `HANDOFF.md` (список
  открытых багов), чтобы не потерять и вернуться к этому позже, а не
  держать в памяти сессии.

## Аналитика — по умолчанию, для каждого нового процесса

Каждый новый хендлер/шаг воронки в этом боте по умолчанию снабжается:

- аналитикой (`add_event` — какой шаг/действие произошло);
- важными деталями в уведомлении админу — строго через
  `bot_services/admin_notifications.py`, не напрямую `bot.send_message`.

Не додумывать самому, какие детали "важные" — если неочевидно, спросить.

## Уведомления админу — тихие по умолчанию

Все уведомления администратору (`bot_services/admin_notifications.py`)
по умолчанию идут **без звука** (`disable_notification=True`).

Со звуком (важные, не трогать без явной просьбы):
- `notify_admin_payment_done` — пользователь подтвердил оплату;
- `notify_care_team` — запрос в отдел Заботы.

Новую функцию уведомления по умолчанию делать тихой; со звуком —
только если Лиза явно скажет, что это важно.

## Персональные данные (152-ФЗ) и политика конфиденциальности

Согласие на обработку ПДн, доступ к политике и удаление данных —
`handlers/start.py` (`consent_accept`, `/policy`, `/delete_me`),
блокировка действий без согласия — `middlewares/consent_gate.py`.
Текст политики — `docs/PRIVACY_POLICY.md`.

**Не упоминать в `PRIVACY_POLICY.md`** место хранения сервера или
конкретных получателей данных (Google Sheets и т.п.) — решение Лизы от
2026-09-06, см. `docs/IDEAS.md` п.1. Сама проблема (сервер вне РФ) не
решена, но не отражать её в документе, адресованном пользователям —
не спрашивать заново, пока Лиза явно не попросит иначе.

Есть ещё отдельная, более старая политика на telegra.ph, прописанная
в BotFather (Bot Settings → Privacy Policy) — показывается в карточке
бота в Telegram, не связана с `docs/PRIVACY_POLICY.md`/`/policy` и
правится не в этом репозитории. См. `docs/IDEAS.md` п.10-11.

## Разделение ролей

- `ADMIN_ID` — владелец бота, доступ к админ-панели (`handlers/admin.py`).
- `NOTIFY_ADMIN_ID` — куда падают уведомления (сейчас это
  `goncharova_help`, 8673829586). Не путать и не объединять — это
  разные роли, менять их независимо друг от друга.
