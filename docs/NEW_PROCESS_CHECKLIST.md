# Чек-лист: создание нового процесса

Используется каждый раз, когда в боте появляется новый процесс —
новый шаг воронки (как шаги Cinemalogy), новый хендлер с реальной
логикой (не просто ссылка/статичный текст), новая интеграция. Общие
правила проекта — в `CLAUDE.md`, здесь — порядок действий и то, что
обязательно нужно сделать, прежде чем считать процесс готовым.

## 1. Бизнес-логика — отдельно от хендлера

Если в процессе есть что-то нетривиальное (навигация, расчёты, работа
с материалами/БД) — выносить в `bot_services/<процесс>/*.py`, как
`bot_services/cinemalogy/frames.py` и `.../materials.py`. Хендлер
(`handlers/<процесс>/*.py`) — только оркестрация: принял
Message/CallbackQuery, вызвал сервисы, отправил ответ.

Так бизнес-логику можно unit-тестировать без aiogram и БД (см. п.5).

## 2. Аналитика — обязательно (см. CLAUDE.md → «Аналитика по умолчанию»)

Каждый значимый шаг процесса — `add_event(telegram_id, "<event_name>",
event_data)`. Имя события — согласованно с уже существующими
(`cinemalogy_start`, `cinemalogy_tariff_selected`, ...), без опечаток:
опечатка в строке-имени события — это тихий баг, его не ловит ни один
тест, кроме теста, который явно проверяет содержимое `user_events`
(см. п.5 и `tests/handlers/test_cinemalogy_tariff.py`).

## 3. Уведомления админу — только через admin_notifications.py

Если процессу нужно уведомлять администратора — новая функция в
`bot_services/admin_notifications.py`, не прямой вызов
`bot.send_message` из хендлера. По умолчанию тихая
(`disable_notification=True`); со звуком — только если Лиза явно
скажет, что это важно (см. CLAUDE.md).

## 4. current_step — сохранять на каждом шаге

`set_parameter(telegram_id, "current_step", "<step_name>")` в начале
хендлера — это то, на чём должен будет заработать возврат пользователя
на последний экран после неизвестной команды (`bot_services/current_step.py`,
`handlers/unknown.py`).

## 5. Материалы (фото/текст/гиф) — через get_material(), с защитой от None

Не хардкодить `file_id`/тексты в коде (кроме уже принятых
исключений вроде стартовой картинки) — заводить материал в
`materials`/`materials_cinemalogy` и читать через сервис-обёртку
(`get_material()` по аналогии с `bot_services/cinemalogy/materials.py`).

`get_material()` возвращает `None`, если материала нет или он
неактивен — **это будет случаться на проде** (забыли завести материал,
выключили его). Хендлер должен явно решать, что делать в этом случае:
- если материал обязателен для экрана — можно упасть с понятной
  ошибкой в логах, но пользователю всё равно нужно отправить что-то
  осмысленное (см. `handlers/cinemalogy/result.py` — текст с
  фолбэком `"Ваш выбор сохранён."`, если `text_row` пуст);
- если материал открывает целую ветку процесса (как список партнёров)
  — прятать ведущую туда кнопку, если материалов нет (см.
  `keyboards/cinemalogy/invitation.py::invitation_keyboard(show_partners=...)`,
  `handlers/cinemalogy/invitation.py`).

Не оставлять `row["field"]` без проверки на `None` там, где материал
может отсутствовать — иначе `TypeError`/`IndexError` прямо в проде.

## 6. Автотесты — обязательно для каждого нового процесса

Без тестов процесс не считается готовым. Минимум:

- **Юнит-тесты** (`tests/unit/`) на всё, что вынесено в
  `bot_services/<процесс>/*.py` по п.1 — чистая логика без aiogram,
  БД — через фикстуру `db` (`tests/conftest.py`, временная sqlite).
- **Тесты на каждый новый хендлер** (`tests/handlers/`) — вызывать
  хендлер напрямую с `fake_message`/`fake_callback`
  (`tests/handlers/conftest.py`, там же фабрика `material(...)` для
  материалов) и проверять:
  1. хендлер не бросает необработанное исключение — это и есть
     главная причина писать эти тесты: любой `NameError`/`TypeError`/
     `IndexError` в проде должен был упасть тестом ещё в разработке
     (проверено на практике — см. историю PR с тестами: баг с
     `start_iamge` ловился именно так);
  2. пользователю ушло то сообщение/фото/клавиатура, которое нужно;
  3. `current_step` и другие `user_parameters` записались верно;
  4. аналитическое событие записалось с точным (без опечаток)
     именем — читать `user_events` напрямую через `sqlite3`, не
     полагаться на то, что "раз не упало — значит верно" (см. п.2).
- Прогнать весь набор перед тем, как считать процесс готовым:
  ```
  cd /home/botuser/telegram-bot
  ./venv/bin/python -m pytest tests/ -v
  ```
  Весь набор должен быть зелёным, не только новые тесты.

## 7. Если процесс вводит новое общее правило

Например, новый паттерн работы с материалами, новый тип уведомления,
новое исключение из "тихих" уведомлений — зафиксировать это в
`CLAUDE.md`, а не только в коде: следующая сессия (в том числе
эта же модель в следующий раз) должна узнать правило из документа,
а не заново находить его при код-ревью.
