13. **Рассылки в боте с явным согласием пользователя** (2026-09-11)
    Архитектура согласована с Лизой, писать код — не сейчас, ждёт

    - **Экран согласия** — отдельный от основного, сразу следующим

      (та же цепочка в `handlers/start.py`, не смешивать тексты —
      `docs/PRIVACY_POLICY.md` п.1.3 уже и сейчас говорит, что согласие
      на рассылки запрашивается отдельно). Кнопки — что-то вроде «📬
      Хочу получать анонсы» / «Не сейчас».
    - **Хранение** — булев флаг + timestamp в `user_parameters`
      (таблица уже существует, см. `delete_user_parameter()`), плюс
      событие в `user_events` (`broadcast_consent_given`/`_revoked`) —
      по образцу уже существующего `consent_given`, как доказательство
      факта согласия для 152-ФЗ.
    - **Отзыв в любой момент** — кнопка «Отписаться от рассылок» в
      разделе «Правовая информация» (`keyboards/legal_info.py`) рядом
      с «Удалить мои данные», плюс команда `/unsubscribe`.
    - **Отправка** — команда для админа (`/broadcast <текст>`, доступ
      по `ADMIN_ID`), выборка по флагу согласия, троттлинг (Telegram
      ограничивает ~30 сообщений/сек разным пользователям), обработка
      ошибок отправки (юзер заблокировал бота → автоматически снимаем
      согласие/помечаем недоступным).
    - **Существующие пользователи** — решено спросить всех уже
      зарегистрированных одним сообщением (по сути та же рассылка, что
      и разрабатываем, только это первый её прогон и адресат — все, не
      только согласившиеся, потому что согласия ещё ни у кого нет).

      должен звучать как уведомление о новой функции/сервисное
      сообщение, а не как маркетинг — иначе это буквально «рассылка
      без согласия на рассылку» до того, как согласие вообще спрошено.
    - **⚠️ Конфликт с политикой v2** — чтобы слать только
      согласившимся, боту в любом случае придётся хранить минимум
      Telegram ID + флаг согласия. Это прямо противоречит текущей
      формулировке «не собираем и не храним персональные данные»
      (см. п.1.8/1.9) — фича не блокируется этим, но расширяет разрыв
      между текстом и кодом, который и так уже в бэклоге. Текст
      политики придётся ещё раз пересматривать, когда будем делать
      этот пункт.
