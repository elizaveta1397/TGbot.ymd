   **Не закрыто:** сама Google-форма никуда не делась и по-прежнему
   собирает те же данные без согласия, если у кого-то уже есть на неё
   прямая ссылка (старые сообщения, скриншоты и т.п.) — источник
   проблемы (форма как таковая) не устранён, устранён только путь к
   ней из бота. Формат — Google Forms, живёт вне репозитория, править
   может только Лиза напрямую в интерфейсе Google.

   Что нашла (проверила содержимое формы 2026-09-11):
   - Форма собирает: ник в Telegram, возраст, семейное положение,
     наличие детей, профессию, опыт терапии, текущие запросы,
     **психиатрические диагнозы (с уточнением и датами)**,
     **медикаментозное лечение (со списком препаратов)**,
     **заболевания щитовидной железы**, **частоту употребления
     алкоголя**, **курение**, **употребление наркотиков**.
   - Диагнозы/медикаменты/зависимости — это специальная категория
     персональных данных (ст. 10 152-ФЗ, данные о здоровье), для неё
     закон требует более строгих оснований обработки, чем для обычных
     ПДн (форма сейчас не даёт вообще никаких).
   - **В самой форме написано: «форма конфиденциальна и не содержит
     ваших персональных данных»** — это неправда буквально по всем
     пунктам выше (ник в Telegram — уже идентификатор). Ссылки на
     `docs/PRIVACY_POLICY.md`/`/policy` в форме нет вообще — она никак
     не связана с политикой бота.
   - Нет ни единого чекбокса согласия на обработку персональных
     данных — ни базового, ни (тем более обязательного для
     спецкатегорий) отдельного явного согласия на обработку данных о
     здоровье.
   - Данные лежат в Google (США) — трансграничная передача, и не
     обычных ПДн, а данных о здоровье — уведомление в РКН под это
     отдельно не проверялось, но по чек-листу из памяти
     `ru-legal-compliance-risks` для спецкатегорий это ещё критичнее,
     чем то же для обычных ПДн.
   - Дополнительно: форма собирает это **прямо сейчас**, в день
     анонса, одновременно с тем, как живая политика бота заявляет «мы
     не собираем персональные данные» — если пользователь сравнит одно
     с другим, разрыв виден сразу.

   Не чинила — решение архитектурно нужно сначала согласовать (сама
   Лиза попросила ничего не делать до согласования). Варианты на

13. **Рассылки в боте с явным согласием пользователя** (2026-09-11)
    Архитектура согласована с Лизой, писать код — не сейчас, ждёт
    отдельной команды.

    - **Экран согласия** — отдельный от основного, сразу следующим
      шагом после «✅ Даю согласие на обработку персональных данных»
      (та же цепочка в `handlers/start.py`, не смешивать тексты —
      `docs/PRIVACY_POLICY.md` п.1.3 уже и сейчас говорит, что согласие
      на рассылки запрашивается отдельно). Кнопки — что-то вроде «📬
      Хочу получать анонсы» / «Не сейчас».
    - **Хранение** — булев флаг + timestamp в `user_parameters`
      (таблица уже существует, см. `delete_user_parameter()`), плюс
      событие в `user_events` (`broadcast_consent_given`/`_revoked`) —
      по образцу уже существующего `consent_given`, как доказательство
      факта согласия для 152-ФЗ.
    - **Отзыв в любой момент** — кнопка «Отписаться от рассылок» в
      разделе «Правовая информация» (`keyboards/legal_info.py`) рядом
      с «Удалить мои данные», плюс команда `/unsubscribe`.
    - **Отправка** — команда для админа (`/broadcast <текст>`, доступ
      по `ADMIN_ID`), выборка по флагу согласия, троттлинг (Telegram
      ограничивает ~30 сообщений/сек разным пользователям), обработка
      ошибок отправки (юзер заблокировал бота → автоматически снимаем
      согласие/помечаем недоступным).
    - **Существующие пользователи** — решено спросить всех уже
      зарегистрированных одним сообщением (по сути та же рассылка, что
      и разрабатываем, только это первый её прогон и адресат — все, не
      только согласившиеся, потому что согласия ещё ни у кого нет).
      **Важно на реализацию**: текст этого самого первого сообщения
      должен звучать как уведомление о новой функции/сервисное
      сообщение, а не как маркетинг — иначе это буквально «рассылка
      без согласия на рассылку» до того, как согласие вообще спрошено.
    - **⚠️ Конфликт с политикой v2** — чтобы слать только
      согласившимся, боту в любом случае придётся хранить минимум
      Telegram ID + флаг согласия. Это прямо противоречит текущей
      формулировке «не собираем и не храним персональные данные» —
      фича не блокируется этим, но расширяет разрыв между текстом и
      кодом. Текст
      политики придётся ещё раз пересматривать, когда будем делать
      этот пункт.
